## 2026-05-09 — Phase 6 ux-7 + bu-9: dashboard versioning + shareable iceberg-anchored snapshots

- **Decision:** Added `dashboard_version(dashboard_id, version, payload, author, message, created_at)` and `dashboard_snapshot(dashboard_id, iceberg_snapshot_id, share_token)` tables in migration `0013_dashboard_versions`. New REST endpoints: `GET /api/v1/dashboards/{id}/versions`, `GET /api/v1/dashboards/{id}/versions/{version}`, `POST /api/v1/dashboards/{id}/versions/{version}/restore`, `POST /api/v1/dashboards/{id}/snapshot`, `GET /api/v1/snapshots/{token}`. Restore inserts a new tip version carrying the prior payload and mirrors it onto the live `dashboard` row in the same flow so history and rendered state cannot diverge. Snapshots store the Iceberg snapshot id verbatim so DuckDB tile re-execution can use `FOR VERSION AS OF`.
- **Why:** ux-7 gives dashboard authors a git-style history + restore. bu-9 turns ad-hoc dashboard sharing into reproducible point-in-time views (the share link renders identical data forever, modulo Iceberg GC). Both are competitor-unique when paired with the existing Iceberg-backed query layer.
- **Updated:** `migrations/0013_dashboard_versions.{up,down}.sql` (new); `internal/api/dashboard_versions.go` (new, ~195 LOC); `internal/api/dashboard_snapshots.go` (new, ~110 LOC); `internal/api/server.go` (5 new routes under `/api/v1`).
- **Origin:** User session 2026-05-09 — Phase-6 ux-7 + bu-9 implementation request.

## 2026-05-09 — Phase 6 Wave 1: pre-flight cost, per-user quotas, schedule-suggest, cost-history index

- **Decision:** Shipped four unique cost-focused control-plane endpoints. (1) `POST /api/v1/cost/preflight` walks `router.ExtractTables` → `synced_tables.row_count × 256 B` to estimate bytes scanned, prices via BigQuery $6.25/TiB on-demand or `UV_SF_USD_PER_TIB` for Snowflake, and joins `budgets.PreflightAllow` for the hard-cap flag. Tables missing from `synced_tables` return as `unknown_tables` (no mock data; INFORMATION_SCHEMA fallback TODO marked for Phase 2). (2) `/customers/{id}/queries` (`queryAnalytics`) now sums `actual_cost_usd` + `estimated_cost_usd` per route. (3) New `internal/quotas/` package with `user_quota(customer_id, user_slug, monthly_cap_usd, hard_block)`, MTD spend computation, `Check(...)` gate, `Upsert`/`List`/`Get`/`Delete`, plus `POST /api/v1/quotas` + `GET /api/v1/customers/{id}/quotas`. (4) `POST /api/v1/cost/schedule-suggest` composes preflight + quota: returns `suggest_schedule:true` when quota would be exceeded OR estimated cost > 50% of the user's monthly cap.
- **Why:** Pre-flight, per-user $ caps with hard-block, and a "don't run, schedule" suggester are competitor-unique cost-governance moves (no listed competitor ships them today). They consume the existing `budgets` workspace cap rather than duplicating it.
- **Updated:** `internal/api/cost_preflight.go` (new), `internal/api/quotas_handlers.go` (new), `internal/quotas/quotas.go` (new package), `internal/api/server.go` (4 new routes + queryAnalytics cost columns), `migrations/0007_quotas_and_cost_index.{up,down}.sql` (new — `user_quota` table + `idx_query_log_customer_cost` partial index).
- **Origin:** User session 2026-05-09 — Phase-6 Wave-1 implementation request (4 items an-1 / de-7 / fo-7 / fo-8).
- **Verification:** `go build ./...` clean; `go vet ./...` clean. Live-warehouse parity test deferred to warehouse-connector-tester run.
- **Deferred:** query_log lacks user_slug attribution → `quotas.MonthSpend` over-accounts by summing customer-wide MTD instead of per-user. Marked TODO(phase-7) inline. INFORMATION_SCHEMA fallback for unsynced tables in preflight also deferred.
